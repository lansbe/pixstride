# imgproxy OSS compatibility

The reference is **imgproxy OSS 4.0.21**, commit `302105ccd183d0038ef71aa11ab4ff3de5f0c989`. The immutable multi-platform image and platform manifests are recorded in [.github/checks/compatibility/reference.json](.github/checks/compatibility/reference.json). This is a compatibility target, not a claim of complete drop-in equivalence.

Compatibility has three separate meanings: accepting a URL, producing the same HTTP/image behavior, and producing equivalent decoded pixels. The synthetic comparison checks dimensions, media type and pixels with per-operation tolerances in [cases.json](.github/checks/compatibility/cases.json). Metadata, alpha, 16-bit samples, animation timing, errors, resource limits and HTTP contracts have separate checks. Compressed bytes need not match. A passing small corpus does not establish equivalence for every image.

## Architecture and dependencies

The built-in engine remains the default. `native-codecs` adds a libvips worker, selected with `PIXSTRIDE_ENGINE=native`. Operations that need this engine select it automatically; builds without it return an explicit unsupported-operation error. Each native image runs in a fresh child, with typed options and bounded binary pipes. No source URL or credential appears in its arguments or inherited environment. Children have no image cache and are killed and reaped after `PIXSTRIDE_PROCESS_TIMEOUT` (default 10 seconds, range 1–120). This is process isolation for resource/lifetime control, not an OS sandbox. libvips and its format libraries remain trusted native code.

`rs-vips` (MIT), with a [documented local C-char/GLib ownership patch](vendor/rs-vips/README.md), wraps dynamically linked libvips (LGPL-2.1-or-later); libvips delegates to system codec, colour and SVG libraries. The native fixture harness also needs a C compiler and libjxl development files; its small animation generator uses the installed encoder API. The container includes its HEIF/JXL plugins and AV1/HEVC encoders. Codec availability depends on the installed system packages. `pixstride capabilities` reports registered operations; `scripts/native_check.py` tests actual codec round trips, including encoders behind the HEIF plugin. Registering a saver alone does not prove a particular HEIF encoder works. x265 has its own GPL licensing terms. The application's MIT license does not replace any dependency's license; retain package notices and corresponding source availability when distributing system libraries.

`cloud-sources` adds Apache OpenDAL (Apache-2.0), Tokio and reqwest with system TLS. The custom SDK transport ignores proxies, disables redirects, filters resolved addresses to public IPv4, checks literal destinations, bounds responses and verifies TLS. `telemetry` adds bounded OTLP/HTTP JSON, direct error-notice clients and signed CloudWatch metrics using reqwest/Tokio. The MIT/Apache-2.0 regex crate supplies bounded wildcard source patterns and replacements. Other direct crates provide bounded GIF encoding, a PNG palette fallback (MIT color_quant), XML parsing, typed worker messages, HTTP dates and platform limits; their licenses are recorded in Cargo metadata. Cargo.lock fixes the dependency graph; Dependabot tracks updates. Linux/macOS on ARM64 and x86-64 remain the supported targets.

## Processing matrix

All OSS processing option names and aliases in the pinned reference parser have a parser implementation. Native rows require `native-codecs`; accepting an option is not a promise that every combination is equivalent.

| Lot | OSS feature/options | Implementation and verification |

| 3 | `preset/pr`, default presets, nested presets, repeated options | Ordered expansion; later values override earlier values. Startup validates definitions. Cycles, depth >8, >64 definitions, >256 expanded options and >16 KiB expansion fail. |

Animation is limited to 256 frames and 50M cumulative pixels. Output format dimension limits apply. |

## Configuration and migration

`IMGPROXY_*` variables are not silently imported. Configure the explicit equivalents below. A `default` preset supplies processing defaults without another duplicate configuration system, for example `PIXSTRIDE_PRESETS='default=q:85/maf:16;thumb=rs:fill:160:160/g:sm'`. Select `/pr:thumb/` in the signed URL; explicit later options override the preset. Preset definitions use `name=option/option`, separated by semicolons or newlines; this differs from imgproxy's configuration file syntax.

| imgproxy setting/family | Pixstride equivalent |
|---|---|
| KEY, SALT and rotation | `PIXSTRIDE_KEY`, `PIXSTRIDE_SALT`: comma-separated matching hex lists, or `_FILE`; independent minimum lengths 32/16 bytes. |
| PRESETS | `PIXSTRIDE_PRESETS` or `PIXSTRIDE_PRESETS_FILE`; bounded definitions with a reserved `default` preset. |
| LOCAL_FILESYSTEM_ROOT | `PIXSTRIDE_LOCAL_ROOT`; relative nested regular files, no symlinks or dot/empty path components; pinned directory descriptors at every level. |
| ALLOWED_SOURCES / download restrictions | Exact `PIXSTRIDE_ALLOWED_HOSTS`, plus per-provider bucket/container allowlists. `PIXSTRIDE_ALLOWED_SOURCES` adds prefix/wildcard restrictions after bounded `PIXSTRIDE_URL_REPLACEMENTS` and `PIXSTRIDE_BASE_URL` rewriting. These restrictions narrow the exact-host/public-address policy. Private destinations, proxy environment variables and remote IPv6 remain unsupported. |
| BIND | `PIXSTRIDE_BIND` IP and `PIXSTRIDE_PORT`; IPv4/IPv6 inbound TCP. `PIXSTRIDE_UNIX_SOCKET` selects Unix instead of TCP, with mode 0600 in an administrator-owned directory not writable by group/others. Existing paths are never unlinked at startup. Healthcheck supports both listeners. |
| CONCURRENCY | `PIXSTRIDE_CONCURRENCY` 1–4; default 1. `PIXSTRIDE_MAX_CLIENTS` defaults to 4, range concurrency–16. Parallel processing requires the native engine. Increasing concurrency above one or clients above four requires `PIXSTRIDE_MEMORY_BUDGET_MIB >= concurrency*1536 + clients*64`, at most 16384. This reserves admission capacity; a container/cgroup remains the hard RSS limit. |
| REQUEST/PROCESSING TIMEOUT | Native `PIXSTRIDE_PROCESS_TIMEOUT` 1–120 seconds, default 10; queue deadline 15 seconds. In-process built-in processing retains structural budgets and has no preemptive CPU deadline. |
| SECRET | `PIXSTRIDE_SECRET` or `_FILE`; Bearer authorization covers health, metrics and image routes. URL signatures are still checked independently. |
| TTL, USE_ETAG, USE_LAST_MODIFIED, LAST_MODIFIED_BUSTER | `PIXSTRIDE_TTL` 0–31536000, default 0 (`no-store`); `PIXSTRIDE_USE_ETAG`, `PIXSTRIDE_USE_LAST_MODIFIED`, `PIXSTRIDE_LAST_MODIFIED_BUSTER`. ETag hashes output bytes; validators are checked after source validation/processing. Cache expiry never outlives the URL. Change the signed cachebuster for processing/configuration changes. |
| ALLOW_ORIGIN | `PIXSTRIDE_ALLOW_ORIGIN`; one explicit CORS value. OPTIONS preflight permits GET/HEAD and selected headers without exposing image data; other methods/headers/origins are refused. |
| AUTO_WEBP, AUTO_AVIF, AUTO_JXL | `PIXSTRIDE_AUTO_WEBP`, `PIXSTRIDE_AUTO_AVIF`, `PIXSTRIDE_AUTO_JXL`; off by default, native engine required. Explicit format wins. Explicit accepted MIME types with positive quality are checked in JXL/AVIF/WebP priority order; `Vary: Accept` is emitted. |
| WATERMARK_PATH, WATERMARK_URL, WATERMARK_DATA, WATERMARK_OPACITY | Corresponding `PIXSTRIDE_*`; select exactly one path/URL/Base64 source. HTTP URL uses the same host/socket policy as image fetches; cloud URLs use the corresponding enabled provider and its allowlist. Opacity is 0–1. |
| PNG_QUANTIZE | `PIXSTRIDE_PNG_QUANTIZE=1` for native palette output. The installed libvips/imagequant quantizer is preferred; a bounded Rust RGBA palette encoder provides a fallback. Its NeuQuant output/quality settings are not pixel-equivalent to imagequant. |
| Encoder configuration | `PIXSTRIDE_JPEG_PROGRESSIVE`, `PIXSTRIDE_PNG_INTERLACED`, `PIXSTRIDE_PNG_QUANTIZE`, `PIXSTRIDE_PNG_QUANTIZATION_COLORS` (2–256), `PIXSTRIDE_WEBP_PRESET`, `PIXSTRIDE_WEBP_EFFORT` (1–6), `PIXSTRIDE_AVIF_SPEED` (0–9), `PIXSTRIDE_JXL_EFFORT` (1–9), `PIXSTRIDE_USE_LINEAR_COLORSPACE` (resampling). Typed settings cross the worker pipe. Palette fallback supports Adam7 interlace. |
| Processing defaults | Corresponding `PIXSTRIDE_QUALITY`, `PIXSTRIDE_FORMAT_QUALITY` (`webp=79,avif=63,jxl=77`), `PIXSTRIDE_STRIP_METADATA`, `PIXSTRIDE_KEEP_COPYRIGHT`, `PIXSTRIDE_STRIP_COLOR_PROFILE`, `PIXSTRIDE_AUTO_ROTATE`, `PIXSTRIDE_PRESERVE_HDR`, `PIXSTRIDE_ENFORCE_THUMBNAIL`, source/frame/result limits and `PIXSTRIDE_SKIP_PROCESSING_FORMATS`. The `default` preset overrides these; explicit URL options override presets. |
| Format preferences | `PIXSTRIDE_PREFERRED_FORMATS` (comma-separated), `PIXSTRIDE_ALWAYS_RASTERIZE_SVG`. Native default preferences JPEG/PNG/GIF preserve an already-preferred source format, then select for alpha/animation. Unformatted SVG remains SVG unless rasterization is configured. |
| SIGNATURE_SIZE, TRUSTED_SIGNATURES | `PIXSTRIDE_SIGNATURE_SIZE` (1–32 bytes, default 32) and `PIXSTRIDE_TRUSTED_SIGNATURES[_FILE]` (up to 16 explicit bypass tokens). Truncated signatures still bind the full original path and support rotation. Trusted signatures intentionally bypass that binding. |
| Prometheus | `/metrics` on the authenticated service listener; optional independent `PIXSTRIDE_PROMETHEUS_BIND` and `PIXSTRIDE_PROMETHEUS_NAMESPACE`. Rust request counts, fixed status classes, active requests and duration histogram. Both listeners use Bearer authorization; no identifying labels. Metric names differ from Go imgproxy. |
| OpenTelemetry | Build `telemetry`; `PIXSTRIDE_OTLP_ENDPOINT`, `PIXSTRIDE_OTLP_METRICS_ENDPOINT`, `PIXSTRIDE_OTLP_LOGS_ENDPOINT` select complete signal endpoints. Optional `PIXSTRIDE_OTLP_AUTHORIZATION[_FILE]`, `PIXSTRIDE_OTLP_SERVER_CERT`, paired `PIXSTRIDE_OTLP_CLIENT_CERT`/`PIXSTRIDE_OTLP_CLIENT_KEY` (PEM paths). `PIXSTRIDE_OTLP_PROPAGATE_EXTERNAL=1` validates W3C traceparent and respects parent sampling. Default IDs come from local OS entropy. |
| Datadog / New Relic | `PIXSTRIDE_DATADOG_KEY[_FILE]` or `PIXSTRIDE_NEW_RELIC_KEY[_FILE]` enable direct OTLP traces, metrics and logs. Optional `PIXSTRIDE_DATADOG_ENDPOINT` / `PIXSTRIDE_NEW_RELIC_ENDPOINT` select a regional base URL; New Relic defaults to the US endpoint. `PIXSTRIDE_NEW_RELIC_APP_NAME` sets service.name. These use vendor OTLP intake, not the Go APM agents or their runtime metrics. |
| Error reporting | `PIXSTRIDE_SENTRY_DSN[_FILE]`, `PIXSTRIDE_SENTRY_RELEASE`, `PIXSTRIDE_SENTRY_ENVIRONMENT`; `PIXSTRIDE_HONEYBADGER_KEY[_FILE]`, `PIXSTRIDE_HONEYBADGER_ENV`; `PIXSTRIDE_AIRBRAKE_PROJECT_ID`, `PIXSTRIDE_AIRBRAKE_PROJECT_KEY[_FILE]`, `PIXSTRIDE_AIRBRAKE_ENVIRONMENT`; `PIXSTRIDE_BUGSNAG_KEY[_FILE]`, `PIXSTRIDE_BUGSNAG_STAGE`. Optional corresponding `PIXSTRIDE_*_ENDPOINT` for Honeybadger/Airbrake/Bugsnag. HTTP 5xx notices contain a generic class/status, no source/headers/stack locals; expected 4xx responses are not reported as vendor errors. |
| CloudWatch | `PIXSTRIDE_CLOUD_WATCH_SERVICE_NAME`, optional `PIXSTRIDE_CLOUD_WATCH_NAMESPACE`, `PIXSTRIDE_CLOUD_WATCH_REGION`, `PIXSTRIDE_CLOUD_WATCH_ENDPOINT`. Request count, duration and errors use the Query API and SigV4. `PIXSTRIDE_CLOUD_WATCH_ACCESS_KEY_ID`, `PIXSTRIDE_CLOUD_WATCH_SECRET_ACCESS_KEY`, optional `PIXSTRIDE_CLOUD_WATCH_SESSION_TOKEN` accept `_FILE` and reload per export; standard AWS credential variables are fallback names. Private metadata credential endpoints remain disabled. |
| Fallback image | `PIXSTRIDE_FALLBACK_IMAGE_PATH`, `PIXSTRIDE_FALLBACK_IMAGE_URL` or `PIXSTRIDE_FALLBACK_IMAGE_DATA`; exactly one. Download failures use this asset through the normal processing pipeline after URL/Bearer authorization. `PIXSTRIDE_FALLBACK_IMAGE_HTTP_CODE` (default 200, zero preserves failure status), `PIXSTRIDE_FALLBACK_IMAGE_TTL` (default no-store). URL expiry still caps TTL. |
| HTTP routing and negotiation | `PIXSTRIDE_PATH_PREFIX`, `PIXSTRIDE_HEALTH_CHECK_PATH` (healthcheck CLI follows them), `PIXSTRIDE_ENFORCE_WEBP`, `PIXSTRIDE_ENFORCE_AVIF`, `PIXSTRIDE_ENFORCE_JXL`, `PIXSTRIDE_ENABLE_CLIENT_HINTS`. Hints supply defaults before presets/explicit options; modern animation selects WebP instead of a static-only format. `PIXSTRIDE_ETAG_BUSTER` invalidates validators; `PIXSTRIDE_SET_CANONICAL_HEADER` emits the source Link header only when explicitly enabled. |
| URL policy | `PIXSTRIDE_ONLY_PRESETS` uses preset names as the first segment. `PIXSTRIDE_ALLOWED_PROCESSING_OPTIONS` restricts explicit option names, `PIXSTRIDE_ALLOW_SECURITY_OPTIONS=0` disables explicit URL limits, `PIXSTRIDE_ARGUMENTS_SEPARATOR` changes URL argument separation, `PIXSTRIDE_BASE64_URL_INCLUDES_FILENAME` ignores the final cosmetic filename segment. Signature verification always precedes decoding/rewriting/expansion. |
| SVG | `PIXSTRIDE_SANITIZE_SVG=1` removes active elements/attributes and external resource references before rendering or passthrough. Bounded inline Base64 PNG/JPEG resources and local CSS fragments are accepted. Without sanitization, unsafe content is rejected. |

Telemetry uses one 64-event queue and a one-second timeout per configured destination, fixed attributes, drop/failure counters and no disk retry queue. Optional notice credentials are sent only in the vendor's required authentication fields. A slow destination can cause queued events to be dropped; inspect the counters. Local collector checks validate OTLP payloads, parent sampling, all four notice protocols, vendor authentication and an independently verified CloudWatch signature. They do not prove account-specific ingestion/IAM or backend dashboard configuration. Go runtime metrics/pprof, vendor-agent-specific instrumentation and cloud secret-manager configuration have no identical Rust implementation. HTTP supports GET/HEAD and bounded CORS OPTIONS preflight, one request per connection; terminate TLS and handle compression/connection reuse at a reverse proxy.

## Storage configuration

Enable only the providers used. Credentials support `_FILE` where shown and are reread for each source request; replacing a mounted token file takes effect on the next request. SDK credential providers handle their own service-account/web-identity exchange during that request. Metadata endpoints on private/link-local IPs remain blocked; supply workload credentials through files or a public identity endpoint instead.

| Scheme | Required policy and credentials |
|---|---|
| `s3://bucket/key` | `PIXSTRIDE_USE_S3=1`, `PIXSTRIDE_S3_ALLOWED_BUCKETS`, exact endpoint hostname in allowed hosts; `PIXSTRIDE_S3_REGION`, optional `PIXSTRIDE_S3_ENDPOINT`; `PIXSTRIDE_S3_ACCESS_KEY_ID`, `PIXSTRIDE_S3_SECRET_ACCESS_KEY`, optional `PIXSTRIDE_S3_SESSION_TOKEN` (each accepts `_FILE`). SDK public identity credential flows are available; private instance/ECS metadata access is refused. |
| `gs://bucket/key`, `gcs://bucket/key` | `PIXSTRIDE_USE_GCS=1`, `PIXSTRIDE_GCS_ALLOWED_BUCKETS`; optional `PIXSTRIDE_GCS_ENDPOINT`; `PIXSTRIDE_GCS_CREDENTIAL[_FILE]` (service-account JSON) or `PIXSTRIDE_GCS_CREDENTIAL_PATH`. Data host allowlisted; public Google identity endpoints are allowed for SDK exchange. |
| `abs://container/key` | `PIXSTRIDE_USE_ABS=1`, `PIXSTRIDE_ABS_ALLOWED_CONTAINERS`, `PIXSTRIDE_ABS_NAME`, optional `PIXSTRIDE_ABS_ENDPOINT`; `PIXSTRIDE_ABS_KEY[_FILE]` or `PIXSTRIDE_ABS_SAS[_FILE]`. Public Azure identity flows use the SDK. |
| `swift://container/key` | `PIXSTRIDE_USE_SWIFT=1`, `PIXSTRIDE_SWIFT_ALLOWED_CONTAINERS`, HTTPS `PIXSTRIDE_SWIFT_ENDPOINT`, `PIXSTRIDE_SWIFT_TOKEN[_FILE]`. Supply a rotating token file, or `PIXSTRIDE_SWIFT_AUTH_URL` (complete Keystone v3 tokens endpoint), `PIXSTRIDE_SWIFT_USERNAME[_FILE]`, `PIXSTRIDE_SWIFT_PASSWORD[_FILE]`, `PIXSTRIDE_SWIFT_PROJECT` and optional `PIXSTRIDE_SWIFT_DOMAIN` (default `Default`). Password authentication obtains a fresh project-scoped token for each request; its identity host must also be allowlisted. Storage endpoint selection remains explicit. |

All four SDK paths have injected-transport tests with synthetic credentials. Stat then conditional range-read binds the body to the stat ETag when available, validates the full returned size, and applies the 64 MiB source ceiling and a 15-second operation deadline. Configure regional endpoints correctly: cloud redirects are refused. Credential exchange traffic and connection reuse are not reported as exact source connection counts. These tests do not substitute for deployment checks against an actual account's IAM, TLS, region and credential policy.

## Qualification

Run after `cargo fetch --locked`:

```sh
cargo fmt --check
cargo clippy --all-targets --all-features --locked --offline -- -D warnings
cargo test --locked --offline
cargo test --all-features --locked --offline
cargo build --all-features --locked --offline
sh .github/checks/abi/run-abi-check.sh .
python3 scripts/native_check.py --binary target/debug/pixstride
python3 scripts/server_check.py --binary target/debug/pixstride --requests 100
python3 scripts/telemetry_check.py --binary target/debug/pixstride
python3 scripts/robustness.py --binary target/debug/pixstride --cases 150
python3 scripts/compatibility.py --binary target/debug/pixstride --reference-binary /path/to/pinned-imgproxy --report /tmp/compatibility.json
```

Build the reference from the exact source commit in reference.json (`go build -o /path/to/pinned-imgproxy ./cli` with its required Go/libvips versions). The comparison report records the executable SHA-256; the CI checks the checkout commit before building it. Native codecs and reference must use comparable libvips/codec builds to assess pixel differences. Reports/corpora/logs stay outside the repository; only synthetic generators and assertions are committed.

CI adds macOS ARM64/Intel checks, native round trips, HTTP/Unix/OTLP integration, a 100-request concurrent soak and deterministic mutation smoke. The Linux AMD64/ARM64 Docker builds run both feature configurations and real native codec checks before release promotion; `python3 scripts/container_check.py --image pixstride:check` also checks the restricted runtime, modern encoders, authorization, SSRF refusal, health and metrics. Its optional `--remote-url` checks a public HTTPS fixture outside mandatory CI. The macOS jobs install Go explicitly to build the pinned reference. A configured workflow is not evidence that remote jobs have run successfully. Docker and the other three platform combinations must pass their own jobs before a release is approved.

The mutation runner uses a fixed seed and bounded malformed PNG/GIF/SVG inputs. It catches parent crashes, native crash signals and harness deadlines. It is not a coverage-guided fuzzing campaign. Longer runs use `--cases`/`--requests` up to 10000. Synthetic soak results are correctness evidence, not an equal-quality performance benchmark. The historical README benchmark does not measure this native engine.

## Deliberate differences and remaining limits

- The complete imgproxy environment-variable surface, vendor agent instrumentation and credential chains are not drop-in compatible. The explicit mappings and exceptions above are the supported migration contract.
- Native children have Linux 1 GiB address-space limits, CPU/fd/core limits, bounded input/output and wall-clock termination. macOS does not apply the Linux address-space limit. Admission memory reservations estimate capacity; they do not measure total RSS or provide a cross-platform hard memory guarantee.
- The native SVG renderer supports a broader static subset but rejects external assets/fonts/styles/scripts. HDR support is format/working-space dependent, not arbitrary scene-linear/HDR-transfer-function equivalence.
- GIF/WebP and JPEG XL input timing/loop cases are checked. Other animated formats, every disposal/blend combination, HDR animations and all metadata/container variants are not exhaustively qualified.
- Dependency/plugin versions, font sets, rounding, compression options and format fallbacks can change outputs. Unsupported combinations fail; inspect the error and the installed capabilities rather than assuming a complete imgproxy replacement.
- PDF/Photoshop/video/RAW previews, per-request watermark images/text, object detection and the Pro internal image cache remain outside the OSS target. No image cache is added.
